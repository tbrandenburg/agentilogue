# Agent integration contracts

**Status: authoritative internal API.** This document is the durable source of truth for the **ownership, boundaries and behavioral invariants** of AGENTILOGUE's provider-neutral agent lane. The code in [`lib/agent/contracts/`](../lib/agent/contracts/) is its canonical app-owned TypeScript definition, not a research sketch or copied protocol. Changes to exported types require code review, tests and an intentional compatibility assessment. This document must change when a locked boundary or invariant changes; implementation tickets hold experiment logs.

The existing AI SDK `/api/chat` lane remains supported. A framework-specific assistant-ui adapter may bypass `AgentProvider` when simpler. The agent path is not an orchestration framework.

Do not re-declare these app-owned shapes in documentation, UI components or provider adapters. Protocol-specific ACP types belong in the OpenCode adapter; assistant-ui's types belong in the browser adapter. `/api/agent` handlers **must** parse untrusted JSON using the exported schemas. Static branded types alone are not validation or authorization.

Do not create placeholder `AgentService`, `AgentRegistry`, orchestration or plugin interfaces. Add an adapter directory only alongside an actual adapter; later use the smallest possible factory if more than one provider needs selection.

## Normative lifecycle and concurrency rules

1. **Ownership and identity.** One UI conversation, one admitted run, the opaque native session and native tool/permission identifiers have separate lifetimes. The server allocates `RunId` and locally correlated permission IDs. A browser-provided conversation ID is not authentication. The HTTP start payload deliberately has **no native session ID, executable, cwd, environment or credentials**; the server authorizes/resolves those. When served beyond strictly trusted local access, authenticate the caller and authorize the project, conversation, run and requested continuation.
2. **Admission versus completion.** `start` returns admission without waiting for the native prompt to finish. A single configured provider can be constructed directly by the server route. ACP allows only one active prompt per native session: hold an explicit per-session lease and reject/constrain concurrent starts for that session. Native identity may be reported later by `session.bound`.
3. **Observation.** `observe` is an `AsyncIterable` whose **first value is an atomic materialized snapshot**. Events after it have strictly contiguous sequence numbers from `snapshot.lastSequence + 1`; no silent gap is allowed. Stop/abort/disconnect **only unsubscribes**; native work continues. `RunSnapshot` stores present state, not an unbounded replay log. A capability of `reconnect: "durable"` requires actual persisted recovery; same-process observation cannot claim it. No process-restart or browser-reload guarantee is implicit.
4. **Native event mapping.** Only the native adapter reads protocol events. It projects allowed fields into the small internal `AgentRunEvent` model; no opaque native payload crosses the contract. Text `message.delta` values append by stable message ID. `tool.updated` patches merge by stable tool-call ID, and an omitted field means unchanged. Native tool calls are **rendered, not re-executed** by the UI. Different native update/replacement semantics must be tested rather than assumed to match ACP or AG-UI.
5. **Permissions/questions.** Permissions are pending native requests with a locally correlated ID and **exact offered option IDs**. `respond` must atomically validate live ownership, option membership, single settlement and a cancellation race; return an error for missing, stale, duplicate or foreign responses. Permission option intent is a UI label, not authorization. Questions are distinct interactions and must be reported unsupported until implemented; do not rebrand a question as permission.
6. **Cancellation.** The `cancel` or permission dispatch receipt is not proof that work stopped. Finish and terminal success/cancel/failure/unknown come from native evidence. On ACP prompt cancellation, settle pending permission RPCs with the protocol's cancelled result and handle concurrent decisions safely. If the native process disappears without terminal evidence, surface `unknown` rather than a false cancellation.
7. **Model/agent selection.** An explicit model or agent is allowed only after server validation against the configured native session. An omitted selection has a defined, tested continuation behavior and must not silently display Default while retaining a prior explicit selection. Do not claim it works merely because the native SDK exposes a field.

**Critical delivery constraint:** ACP permission replies must be independently deliverable while the agent is blocked in a live prompt. [`AssistantTransport` queues ordinary commands](https://www.assistant-ui.com/docs/runtimes/custom/assistant-transport), while [AG-UI interrupt/resume](https://www.assistant-ui.com/docs/runtimes/ag-ui/runtime-options) is not automatically the same as answering a pending ACP request. The chosen transport must demonstrate independent control. The internal observation model is **not** a new browser streaming protocol: adapt it to the selected maintained transport.

## Secondary contracts and change policy

| Type group                | Meaning we preserve                                                                                                                                       | What may change with real provider evidence                               |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| IDs and admission         | Distinct ownership, no mix-up of run and native session; admission before completion                                                                      | Representation, native binding timing, retry/idempotence rules            |
| `AgentCapabilities`       | Advertise actual configured integration behavior, not provider branding; distinguish continuation from cold reattach and same-process from durable replay | Capability detail, optional extensible feature categories                 |
| `RunSnapshot` and updates | Atomic initial state plus gap-free sequenced changes; observation separate from control                                                                   | Buffering, replay storage, per-observer reconnect contract                |
| `AgentRunEvent`           | Stable message/tool identity, explicit deltas versus patches, native tools not run twice                                                                  | Additional **needed** normalized events, multimedia content semantics     |
| Permission decision       | Exact offered IDs, one settlement, cancellation race handled                                                                                              | Optional question/elicitation variants and native approval scopes         |
| Outcome/control receipts  | Local dispatch and observed native termination are different                                                                                              | Exact error taxonomy and child-work settlement details                    |
| Discovery/history/export  | Preserve native features without forcing a lowest-common-denominator API                                                                                  | Add optional capabilities and operations on evidence, not as placeholders |

Type definitions are **authoritative now**, not prototypes. Changing a TypeScript signature is an API change requiring review, tests, and updated consumers; it does not automatically require an architecture rewrite. The locked boundaries/invariants above are higher stability commitments. Native conformance evidence can justify a revision, which must be recorded in the relevant implementation PR.

## Provenance and deliberate non-adoptions

Our app-owned provider port is informed primarily by [Archon's provider interface](https://github.com/coleam00/Archon/blob/c5af8035/packages/provider-contract/src/agent-provider.ts) and [node-red-agents' execution lifecycle](https://github.com/tbrandenburg/node-red-agents/blob/7f738528/packages/node-red-agents/nodes/agent/lib/execution/lifecycle.js). Capability differentiation draws from [Archon capabilities](https://github.com/coleam00/Archon/blob/c5af8035/packages/provider-contract/src/capabilities.ts), native permission mapping from [Omnigent](https://github.com/omnigent-ai/omnigent/blob/0b171e29/omnigent/harnesses/opencode_native/permissions.py), and session/history operations from [MADE](https://github.com/tbrandenburg/made/blob/17292a5a/packages/pybackend/agent_cli.py). Atomic snapshot/subscription semantics were informed by [AHP](https://microsoft.github.io/agent-host-protocol/specification/subscriptions.html); this is **not** AHP adoption. [AG-UI events](https://docs.ag-ui.com/concepts/events) inform the browser projection without becoming our native provider interface. [A2A](https://a2a-protocol.org/latest/specification/) is a possible remote task adapter, not an ACP session clone. [MCP](https://modelcontextprotocol.io/specification/2026-07-28/server) remains a separate tool/resource boundary.

These references informed the _behavior and boundaries_, not a claim that code was copied, is conformance-certified, or implements those other protocols.

## Verification and enforcement

- **Before merge:** frozen-lockfile installation; formatter, linter, tests, and `bunx tsc --noEmit`; prove the HTTP schema tests reject malformed and unauthorized-shaped **fields**. Runtime schemas cannot establish actual caller/project ownership—that requires live route authorization tests.
- **With the OpenCode adapter:** version-pin ACP v1 and official SDK; test process lifecycle, one active prompt per session, permission/cancel races, text and partial tool updates, session configuration and loss. Compare serve/SDK if ACP behavior is insufficient.
- **With the browser integration:** validate the selected maintained transport against live permissions, cancellation, observation gaps, two conversations, disconnection and the untouched `/api/chat` lane. Exercise desktop and narrow-screen manual E2E. Attach commands, observed versions and results to implementation PRs.
- **Before promoting a capability:** require native test evidence **and** browser E2E. A passing type/schema test is necessary, not evidence of a working native adapter. Unimplemented features must report unsupported.
