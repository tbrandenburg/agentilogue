# OpenCode agent API (trusted local only)

The ACP provider is opt-in. Set `AGENT_API_ENABLED=1`, `AGENT_TRUSTED_LOCAL=1`, and `OPENCODE_CWD=/absolute/project/directory`; optionally set server-owned `OPENCODE_EXECUTABLE`. The project `dev` and `start` scripts bind Next.js to `127.0.0.1`. The route itself has no authentication and cannot verify the TCP peer; its URL and Host are not caller identity. Do not override the bind address or expose it through a public interface, reverse proxy, shared network, or to other users. `AGENT_TRUSTED_LOCAL` is an explicit operator assertion, not caller authorization. A matching conversation ID only correlates a run and does not authorize a caller.

The OpenCode UI uses the maintained `useExternalStoreRuntime` because its lifecycle is split across a JSON start/control API, a separately reconnectable observation stream, and independent permission/cancel requests. `useAssistantTransportRuntime` owns command submission through a transport request/stream and its ordinary command queue does not provide these independent native controls while that request is active. The observation stream still uses assistant-ui's maintained `AssistantTransportEncoder`/`AssistantTransportDecoder`; the external-store adapter owns the reconnect and transcript projection explicitly. This is one deliberate runtime path, not a new browser wire protocol.

The route accepts only `localhost` or `127.0.0.1` Host values that match the request's expected origin. POST requests must use `application/json`; browser requests must carry a matching Origin, or—when the browser omits Origin—a matching Referer. A present Fetch Metadata site value must be `same-origin`. GET observations use the same source/Host checks. Missing or mismatched source information is rejected before provider lookup or control dispatch. This is browser-origin protection, not caller authentication.

`POST /api/agent` accepts either `{ conversationId, input: [{ type: "text", text }] }` and returns an accepted, server-generated run ID, or a control body from `AgentControlBodySchema`. `GET /api/agent?runId=<id>` observes updates encoded by the maintained `assistant-stream` `AssistantTransportEncoder` for `@assistant-ui/react` 0.15.25 (`protocol: "assistant-transport"`), not an app-specific wire format. Each observer gets the current snapshot followed by gap-free updates; reconnecting in the same process starts from a fresh snapshot. Closing the request only detaches the observer. Runs and snapshots live in memory and are lost on server restart; a restart/child loss has an unknown outcome. Slow observers that exceed the bounded live queue receive an error and can reconnect for a fresh snapshot. There is no cold reattach or durable persistence.

The observation route validates and obtains the initial snapshot before returning stream headers; missing or expired run IDs return HTTP 404, while a retained `unknown` run is sent as its terminal snapshot. The browser retries transient observation failures with bounded backoff; HTTP 403/404 or exhausted retries show a disconnected state with a manual Retry action. The browser retains the admitted run ID and Stop control until a native terminal snapshot arrives.

The first run for a UI conversation creates an ACP session; later runs in that same conversation use the provider's in-memory session binding and ACP `session/load` with the same configured absolute cwd. Load-time history replay is suppressed from the new run's browser projection, while OpenCode retains that history as model context. A different conversation receives a different native session. The browser never supplies native session IDs, cwd, executable, environment, or credentials. Model/agent selection is disabled because the proof did not establish a safe explicit/unset policy. This ACP client advertises no filesystem capability or filesystem handlers. OpenCode's own native tools remain provider-executed using the configured cwd and OpenCode permission policy; this is not a filesystem sandbox. The provider reports only vetted text, tool, permission, session, and terminal projections; it does not expose raw ACP payloads.

The conversation-to-session binding exists only in this server process. A process restart does not restore it, even though OpenCode itself can load persisted sessions. If a child is lost without a prompt result, that run is `unknown` and its conversation lease remains blocked rather than risking overlapping prompts on an uncertain session.

Known completed run receipts are retained in memory for 30 minutes after completion, then lazily removed on the next provider entry point. After expiry, observing or controlling that run returns `Unknown run`. Running runs and runs with an `unknown` outcome are never expired; an unknown outcome continues to hold its conversation lease indefinitely. Expiring a run receipt does not remove the conversation's native session binding, so live conversations can continue through their existing OpenCode ACP session.

With OpenCode 1.18.32, the production provider was exercised against a disposable project after removing ACP filesystem client capabilities: OpenCode completed a native file write after an offered `once` permission was approved, and a separate write was rejected with the offered `reject` option and created no file. This proves those two native actions in that binary/configuration; it does not establish a sandbox or general filesystem confinement.

This API is for trusted single-user local development only. It is not suitable for production or untrusted/shared network deployment until authenticated caller and project authorization is implemented.
